# 2.23* — сайт-портфолио

## Структура
```
index.html          — главная (сетка проектов)
project.html         — страница проекта (шаблон)
style.css / main.js  — стили и рендеринг
data/content.js      — ВЕСЬ контент сайта (тексты, фото, видео, аудио, ссылки)
images/              — фотографии проектов
audio/               — аудиодорожки проектов
icons/               — svg-иконки (back, prev/next, курсор)
admin/admin.html      — редактор контента
```

Сайт статический: `index.html` и `project.html` читают `data/content.js` и сами
строят страницу. Менять контент можно без прикосновения к HTML — через
`data/content.js` (руками) или через `admin/admin.html` (визуально).

## Что нового в этой версии
- Сетка выстроена по 12-колоночной системе (1512px, margins 40pt, gutter 8pt),
  все отступы (48pt между рядами карточек, 12pt картинка→текст, 32pt
  стрелки→контент, 220pt шапка→блок с картинками) — как в Figma-макете.
- Шрифт — Inter везде. Лого 60pt regular, заголовок проекта 90pt regular,
  заголовок About 40pt regular, весь остальной текст 12pt.
- Стрелки над галереей теперь **листают галерею проекта** влево/вправо
  (не переключают проекты).
- Клик по фото или видео в галерее открывает **лайтбокс** (полноэкранный
  просмотр) со своими стрелками пролистывания.
- В галерею можно добавлять **видео по ссылке** (YouTube) — тянется превью
  автоматически. Есть выбор ориентации (горизонтальное/вертикальное) —
  от этого зависит, как видео вписывается по высоте в общий ряд с фото.
- Под галереей, перед About — блок **аудиодорожек** с плеером
  (play/pause, полоса прогресса, название трека).
- Полоска-разделитель перед About убрана.
- Кастомный курсор (маленькая точка + едва заметный шлейф из точек,
  которые с лёгкой задержкой следуют за курсором). Работает только на
  устройствах с мышью — на тач-экранах не активируется и не мешает.
- Резиновая вёрстка: сетка, шрифты и отступы плавно масштабируются от
  десктопа до мобильного экрана.

## Как открыть локально
Открой `index.html` двойным кликом — работает без сервера. Шрифт Inter
подтягивается из Google Fonts при наличии интернета, иначе — системный шрифт.

## Редактор контента (admin/admin.html)
Работает в Chrome / Edge / Яндекс.Браузере (нужен File System Access API —
Safari и Firefox пока не поддерживают).

1. Открой `admin/admin.html`
2. «Выбрать папку сайта» → корневая папка (там, где `index.html`)
3. Разреши доступ на чтение и запись
4. Редактируй тексты, фото, видео (по ссылке), аудио, порядок проектов
5. «Сохранить» — пишет в `data/content.js`, `images/`, `audio/`
6. Обнови сайт (F5), чтобы увидеть изменения

При каждом открытии `admin.html` нужно заново выбрать папку — браузер не
хранит доступ между сессиями из соображений безопасности.

**Важно:** редактор пишет файлы **на диск того компьютера, где он открыт**,
через локальный доступ к папке. Он не может писать напрямую в сайт,
опубликованный на GitHub/Vercel — значит, работать с ним нужно на локальной
копии репозитория, а затем отправлять изменения на сервер (см. ниже).

## Как выложить в интернет через GitHub

### 1. Публичный сайт (index.html, project.html) — виден всем

**Вариант А — Vercel (проще всего, у тебя уже есть опыт):**
1. Создай репозиторий на GitHub, залей туда содержимое этой папки
   (`git init`, `git add .`, `git commit -m "site"`, `git push`)
2. На vercel.com → New Project → Import из этого репозитория
3. Никаких настроек сборки не нужно (это статические файлы) — Deploy
4. Получишь публичный URL вида `2-23-site.vercel.app`

**Вариант Б — GitHub Pages:**
1. Залей репозиторий на GitHub (можно публичный)
2. Settings → Pages → Source: выбери ветку `main` и папку `/ (root)`
3. Через пару минут сайт появится на `https://<твой-логин>.github.io/<репозиторий>/`

Оба варианта отдают только статику — `admin/admin.html` тоже станет доступен
по прямой ссылке (`.../admin/admin.html`), просто на него никто не наткнётся
случайно, если не публиковать ссылку. Если это достаточно — ничего больше
делать не нужно.

### 2. Если хочешь закрыть админку паролем/доступом

Так как `admin.html` не имеет собственного сервера — это просто файл в
браузере — «закрыть по паролю» можно только на уровне хостинга:

**Проще всего — не публиковать её вообще.**
Держи админку только локально (просто открывай файл с компьютера, папка сайта
— это тот же git-репозиторий, который ты потом пушишь на GitHub). Тогда в
интернет утекает только сам сайт, а `admin/` можно даже не пушить в публичный
репозиторий — добавь `admin/` в `.gitignore` и работай с ним из локальной копии.

**Если всё-таки нужен доступ по ссылке из любого места:**
- **Vercel Password Protection** (платная функция Pro-плана) — включается в
  настройках проекта, закрывает весь деплой или конкретный путь единым
  паролем без написания кода.
- **Отдельный приватный репозиторий** только с папкой `admin/`, задеплоенный
  отдельно от основного сайта (например, отдельный Vercel-проект) — доступ
  контролируется через приватность самого репозитория плюс, при желании,
  Vercel Password Protection сверху.
- Помни: даже за паролем админка всё равно будет работать только с той
  папкой сайта, которую ты откроешь ей локально через «Выбрать папку сайта» —
  то есть удалённый доступ имеет смысл, только если ты открываешь её на
  устройстве, где есть локальная копия репозитория.
